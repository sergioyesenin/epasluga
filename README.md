
# Е-Паслуга — личный кабинет (PWA)

Учебный прототип личного кабинета белорусского портала электронных услуг «Е-Паслуга».
Работает как обычный сайт и как устанавливаемое приложение (PWA): открывается с экрана
«Домой», работает без сети, присылает напоминания о сроках платежей.

Внутри — каталог услуг с поиском своими словами, жизненные ситуации с пошаговыми маршрутами,
заявления и их статусы, документы, «Почта гражданина» и семейный раздел **«Далонь»**
(«всё о семье — в одной ладони»): начисления всей семьи, напоминания, роли и согласия,
оплата одной кнопкой и квитанции.

> Все данные условные и хранятся только в браузере (localStorage). Оплата, SMS, ЭЦП и биометрия —
> демонстрационные: деньги никуда не уходят, сервера нет.

## Запуск

Нужен Node.js 20+ (проверено на 22).

```bash
npm ci            # установить зависимости
npm run dev       # режим разработки: http://localhost:5173
npm run build     # проверка типов + сборка в dist/
npm run preview   # раздать сборку: http://localhost:4173
npm run lint      # ESLint
```

Service worker (офлайн, обновления, уведомления) включается **только в сборке** —
проверяйте PWA через `npm run build` + `npm run preview`, а не через `npm run dev`.

Демо-вход: любой номер белорусского оператора, код из SMS — `1234`.

## Как установить на телефон

Приложению нужен HTTPS (или `localhost`). Удобнее всего выложить `dist/` на GitHub Pages
или любой статический хостинг — сборка работает из подпапки (`base: './'` + hash-роутер).

**Android (Chrome, Edge, Samsung Internet).** Откройте сайт — на главной появится карточка
«Установите Е-Паслугу на устройство» → «Установить». Либо меню браузера → «Установить приложение».
Долгое нажатие на значок покажет ярлыки: «Далонь», «Мои услуги», «Поиск услуг».

**iPhone и iPad (Safari).** Кнопка «Поделиться» → «На экран „Домой“» → «Добавить».
Карточка с этой инструкцией появляется на главной сама. Уведомления на iPhone работают
только у приложения, добавленного на экран «Домой» (iOS 16.4+).

**Компьютер (Chrome, Edge).** Значок установки в адресной строке или пункт
«Установить приложение» внизу бокового меню.

## Что делает PWA

- **Манифест** (`vite.config.ts`): название, `lang: ru`, `display: standalone`, цвета, иконки
  192/512 (обычные и maskable), ярлыки. `start_url` и `scope` — относительные (`./`).
- **Service worker** (Workbox через `vite-plugin-pwa`): в precache вся оболочка, все ленивые чанки
  экранов и шрифт Onest (`woff2`), поэтому после первого визита без сети открывается любой экран,
  даже ещё не открытый. Любой переход внутри приложения без сети отдаёт закэшированный `index.html`.
- **Обновления**: новая версия не подменяет старую молча — появляется тост
  «Доступна новая версия — Обновить». Раз в час приложение само проверяет обновления.
- **Без сети**: полоса «Нет сети» под шапкой. Каталог, ситуации, документы и «Далонь» открываются
  из памяти устройства; отправка заявлений и оплата ждут интернет (кнопки неактивны и объясняют почему).
- **Установка**: своя карточка вместо мини-панели браузера (`beforeinstallprompt`), на iOS —
  инструкция. В установленном приложении карточка не показывается; её можно закрыть на 14 дней.
- **Напоминания** («Далонь» → «Напоминания»): разрешение спрашивается только по кнопке,
  уведомление показывает service worker (`registration.showNotification`), клик открывает «Далонь».
  Это локальное демо: настоящий push требует сервера (Web Push + VAPID).
- **Мобильный режим**: нижние вкладки, `viewport-fit=cover` и отступы `env(safe-area-inset-*)`,
  зоны нажатия от 44 px, без горизонтальной прокрутки.
- **Вход по биометрии**: как в банковских приложениях — включается после первого входа по SMS
  на конкретном устройстве и дальше заменяет SMS. Места для вызовов WebAuthn
  (`navigator.credentials.create/get`) отмечены в `src/lib/biometric.ts`.

Иконки рисует `scripts/make_icons.py` (нужен только Pillow): `python scripts/make_icons.py`.

## «Далонь»

Семейная панель, а не кошелёк: деньги не хранятся в Е-Паслуге, платёж проводит банк через ЕРИП.

| Экран | Маршрут | Что там |
| --- | --- | --- |
| Панель | `#/family` | Растение семьи: до 4 человек — росток (люди — листья), с 5 — цветок (люди — лепестки; порог `FLOWER_MIN_PEOPLE` в `src/lib/dalon/plant.ts`); имущество (VW Polo, квартира, дача) — листья на стебле. Значки: число счетов / оплачено / нет доступа; нажатие ведёт к начислениям. Под растением — итог. Начисления по членам семьи, выбор, «Оплатить выбранные», календарь сроков |
| Напоминания | `#/family/reminders` | Скидка 50 % на штраф ГАИ, ближайшие сроки, push-демо, каналы (кабинет, push, SMS, почта) и темы |
| Семья и права | `#/family/people` | Состав семьи по записям ЗАГС (брак, рождение), «видит» даёт связь ЗАГС, «платит» супруги включают сами; связь закрывают только записи о расторжении брака или смерти; в 18 лет представительство прекращается само; имущество; демо-блок «События из реестра ЗАГС»; журнал действий |
| История | `#/family/history` | Оплаченное за год, фильтр по члену семьи, скачивание квитанций |
| Оплата | `#/family/pay?ids=…` | ЕРИП или карта, демо-успех и демо-сбой «Платёж не прошёл. Деньги не списаны» с «Повторить» |
| Профориентация | `#/family/career/:id` | Тест (10 вопросов) → профиль, направления подготовки, колледжи и вузы по городу (Минск по месту жительства). Учреждения и специальности — условные, не официальный перечень |
| РТ / ЦТ / ЦЭ | `#/family/testing/:id` | Мастер регистрации внутри Е-Паслуги: вид, предметы, дата и пункт, согласие; оплата через «Далонь» (ЕРИП/карта, демо-сбой); заявка и пропуск — в «Моих услугах», день тестирования — в «Напоминаниях». Правила, даты и цены — демо, уточнять в РИКЗ |

Демо-данные «Далони» можно вернуть к началу внизу экрана «История» или кнопкой «Сбросить демо» на экране «Семья и права».

На панели — блок «Система предлагает»: ребёнок в 9 классе → «Подать документы в колледж (ССУЗ)», в 11 классе → «Подать документы в вуз» и регистрация на РТ / ЦТ / ЦЭ. Демо-переключатель класса показывает второй сценарий; то же предложение — плашкой на главной.

## Маршруты

Роутер — `createHashRouter`, поэтому адреса вида `…/#/catalog`.

| Маршрут | Экран |
| --- | --- |
| `#/` | Главная (гость — о портале; после входа — сводка, «Далонь», заявления) |
| `#/login` | Вход: SMS, биометрия, ЭЦП |
| `#/catalog` | Каталог: `?view=situations\|list\|cats\|favs`, `?cat=…`, `?q=…` |
| `#/situation/:id` | Жизненная ситуация с пошаговым маршрутом |
| `#/passport/:id` | Паспорт ситуации (BA-документ, доступен по прямой ссылке с ситуации) |
| `#/service/:id` | Карточка услуги и форма заявления |
| `#/status/:id` | Статус заявления (только после входа) |
| `#/profile` | Кабинет: `?tab=overview\|apps\|docs\|mail\|repo\|data` (только после входа) |
| `#/notifications` | Уведомления (только после входа) |
| `#/family/*` | «Далонь» (только после входа) |
| `#/support`, `#/about` | Поддержка, о портале |
| любой другой | Страница 404 «Страница не найдена» |

Каждый экран — отдельный чанк (`React.lazy`, см. `src/app/router.tsx`), пока он грузится, виден
скелетон. Заголовок вкладки задаётся в `handle.title` маршрута, у карточек услуги, ситуации и
паспорта — самой страницей (`useDocumentTitle`).

## Реестр ситуаций: текущее состояние

Прототип реализует **41 ситуацию** из мастер-реестра (31 жизненная — LS + 10 деловых — BS)
и **8 сквозных компонентов (XC)**.

### Где что лежит

| Файл | Что содержит | Кто трогает |
| --- | --- | --- |
| `src/data/services.ts` | 174 базовые услуги (сгенерированы `legacy/generate_data.py`) | **не редактировать вручную** — перезапишется |
| `src/data/servicesExtra.ts` | Новые услуги для ситуаций Волны 1–3 (`ls-01-birth-reg`, `bs-07-tech-inspection-status` и т.д.) | **сюда добавляются новые услуги** |
| `src/lib/search.ts` | Мержит `services` + `servicesExtra` в один каталог | не трогать без необходимости |
| `src/data/situations.ts` | 41 ситуация (10 старых + 31 из реестра), с `registryId`, `digitalState`, `priority`, `gap`, `xcDeps` | правки по согласованию с BA |
| `src/data/xcComponents.ts` | 8 сквозных компонентов (`XC-01…XC-08`) с `affectedSituations` | правки по согласованию с BA |
| `src/data/situationPassports.ts` | 5 паспортов ситуаций Волны 1 (`LS-01`, `LS-13`, `LS-19`, `LS-23`, `BS-07`) | **новые паспорта — сюда** |

### Правило для новых услуг

Если добавляете новую услугу:

1. **Не редактируйте `src/data/services.ts`** — он генерируется. Либо добавьте в `servicesExtra.ts`, либо доработайте генератор `legacy/generate_data.py` и перегенерируйте.
2. Все поля `Service` обязательны, кроме `digitalState`, `priority`, `xcDeps` — они опциональны.
3. `id` — уникальный, формат `xxx-xxx` (например, `ls-01-birth-reg`). Он используется в URL `#/service/:id`.
4. `code` — код административной процедуры (например, `200.5.1`). См. раздел про верификацию ниже.

### Приоритеты и состояния

- `digitalState`: `green` (🟢 онлайн), `yellow` (🟡 частично), `red` (🔴 офлайн).
- `priority`: `P1` (готовые «кирпичи», высокая массовость), `P2` (нужны НПА/интеграции), `P3` (институционально сложно).
- `gap` — что нужно изменить (декомпозировать), отображается на странице ситуации.
- `xcDeps` — от каких XC-компонентов зависит маршрут.

## Паспорт ситуации и юридическая верификация

### Что такое паспорт

**Паспорт ситуации** — это BA-документ, который фиксирует для каждой ситуации:

- владельца процесса (ведомство-«хозяин»);
- триггер (что запускает ситуацию);
- правовую основу (НПА + коды процедур);
- участников и их ИС;
- целевой маршрут (что онлайн, что офлайн и почему);
- данные, их источники и master-источники;
- каналы и результат для пользователя;
- метрики (доля онлайн, время, визиты, отказы);
- зависимости от XC.

Он нужен, чтобы **другой разработчик или BA вошли в контекст без переписки**:
что за ситуация, откуда взялись коды, где узкие места, почему выбраны такие шаги.

### Зачем до верификации

Паспорта написаны **до юридической верификации** — это осознанно. В них зафиксированы **рабочие гипотезы** из мастер-реестра, а не подтверждённые данные. Если ждать верификации, другие части прототипа (UI, ситуации, XC) останутся без контекста — разработчик не поймёт, откуда взялись шаги и куда смотреть.

Поэтому:

- у всех паспортов стоит `legalVerificationRequired: true`;
- в `PassportPage` (UI) показывается жёлтая плашка **«Правовая основа требует верификации»**;
- в поле `legalBasis` каждого паспорта вручную прописано `⚠️ НЕ ВЕРИФИЦИРОВАНО: …`.

### Что именно нужно верифицировать

1. **Коды процедур** во всех услугах (`servicesExtra.ts`, `services.ts`). В мастер-реестре они помечены как гипотезы. Например:
   - `3.104.01` (техосмотр для банка) — **скорее всего, вымышленный**, проверить первым делом.
   - `3.105.01` (зарядная станция) — **скорее всего, вымышленный**.
   - `3.30.01`, `3.28.01`, `200.7.1`, `200.7.2`, `3.18.01`, `3.16.04`, `3.21.02`, `3.19.01`, `3.13.01`, `3.47.05`, `3.00.19.1`, `3.50.01` — проверить.
2. **Номера НПА** в `legalBasis`: Постановление № 221, распоряжение № 119р, указы 2026 г. — сверить с действующими редакциями.
3. **Сроки** (`timeToComplete`) и **стоимость** (`cost`) — по реестру административных процедур.
4. **Ведомство-владелец** (`owner` в паспорте, `orgName` в услуге) — совпадает ли с реальным.

### Официальные источники

- Реестр административных процедур — nces.by, портал «Е-Паслуга».
- Постановление Совета Министров № 221 от 17.10.2018 (действующая редакция).
- Распоряжение Президента № 119р.
- Сайты ведомств: mvd.gov.by, mintrud.gov.by, minjust.gov.by, nalog.gov.by, edu.gov.by, minzdrav.gov.by, gki.gov.by, customs.gov.by, mpt.gov.by, msa.gov.by, minenergo.gov.by.

### Как верифицировать

Промпт для BA/LLM с официальными источниками и списком сомнительных кодов — в задаче на верификацию (передаётся отдельно). После отчёта:

1. Обновить `code`, `officialTitle`, `timeToComplete`, `cost`, `orgName` в `servicesExtra.ts` (или `services.ts` через генератор).
2. Обновить `legalBasis`, `owner`, `metrics.time` в `situationPassports.ts`.
3. Если код подтверждён — снять `legalVerificationRequired: true` у соответствующего паспорта.
4. Если код не найден — либо заменить на найденный, либо явно пометить `legalBasis: 'код не найден, требуется уточнение в НЦЭУ'`.

## Что почистить перед продакшеном (BA-блоки)

В прототипе сейчас много «внутренней» информации для BA и разработчиков — она полезна при разработке, но **не должна попасть в пользовательский продакшен**. Список того, что нужно почистить:

### 1. Паспорта ситуаций (`#/passport/:id`)

- **URL и страница `PassportPage`** — доступны любому, кто знает ссылку. Для продакшена — либо скрыть за авторизацией (роль «BA»), либо убрать маршрут совсем.
- **Ссылка «Открыть паспорт ситуации»** на `SituationPage` — показывается пользователю. Убрать для продакшена.
- **Поля `owner`, `legalBasis`, `targetRoute`, `data`, `metrics`, `dependencies`** — терминология BA, не для пользователя.

### 2. Блок «Сквозные компоненты» в `DataTab`

- В `#/profile?tab=data` внизу — список всех 8 XC с ID (`XC-01`, `XC-02`), назначением и ссылками на ситуации. Терминология BA, не для пользователя.
- **Что делать:** убрать блок или переформулировать по-человечески («Что улучшим в первую очередь» уже есть в `OverviewTab` — этого достаточно для пользователя).

### 3. Блок «Что улучшим в первую очередь» в `OverviewTab`

- В `#/profile` на вкладке «Обзор» — карточка с XC-01, XC-02, XC-06 и ссылками на ситуации. Это ближе к пользователю, но всё равно содержит ID компонентов.
- **Что делать:** либо убрать ID (`XC-01`), оставив только названия и ссылки, либо убрать блок целиком.

### 4. Бейджи `digitalState` и `priority` в каталоге и на странице ситуации

- В `CatalogCard` — бейджи «Онлайн»/«Частично»/«Офлайн» и `P1`/`P2`/`P3`.
- На `SituationPage` — те же бейджи рядом с заголовком.
- **Что делать:** бейджи состояния (`digitalState`) можно оставить — они полезны пользователю. Бейджи приоритета (`P1`/`P2`/`P3`) — это внутренняя информация BA, **убрать**.

### 5. Поле `gap` («Что нужно изменить (декомпозиция)»)

- На `SituationPage` — жёлтая карточка с текстом «Проактивное уведомление есть → нужен маршрут восстановления».
- **Что делать:** для пользователя переформулировать («Что мы улучшим в этой ситуации») или убрать.

### 6. Карточка «Сквозные компоненты» в правой колонке `SituationPage`

- Показывает `XC-01`, `XC-02` и т.д. с назначением. BA-терминология.
- **Что делать:** убрать.

### 7. Бейдж `priority` в бейджах ситуаций

- См. п. 4.

### 8. Комментарии в коде

- В `servicesExtra.ts`, `situations.ts`, `situationPassports.ts`, `xcComponents.ts` — комментарии вида `// Юридические коды процедур — рабочие гипотезы, требуют верификации`, `// ── Волна 2 (P2) — часть 2б ──` и т.п.
- **Что делать:** после верификации — обновить или убрать. Для продакшена эти комментарии не нужны, но и не мешают (они не попадают в бандл).

### Что требует бэкенда и интеграций

| Что | Сейчас в прототипе | Что нужно |
| --- | --- | --- |
| Вход | флаг `epasluga-auth` в localStorage, SMS-код любой | авторизация через МСИ (OpenID Connect), сессия в httpOnly-cookie, выход на сервере |
| Биометрия | отметка «включено» в localStorage | WebAuthn: `navigator.credentials.create/get` с challenge от сервера, проверка подписи на сервере |
| Заявления, уведомления, документы | демо-данные в localStorage, номер из `Date.now()` | API ЕПЭУ: регистрация заявления, статусы, юридически значимые уведомления, хранилище документов |
| Оплата в «Далони» | имитация с квитанцией | ЕРИП (АИС «Расчёт»): выставление и подтверждение платежей, квитанции от банка |
| Состав семьи, события ЗАГС | демо-панель событий | реестры ЗАГС (ГИС «Регистр населения»), права на имущество — ГАИ (транспорт), ГКИ/ГУП «Национальное кадастровое агентство» (недвижимость) |
| Напоминания | локальные уведомления service worker | Web Push с VAPID-ключами: подписка на сервере, рассылка из бэкенда |
| ИИ-помощник | шаблонный ответ | сервис ответов с базой знаний портала и журналом обращений |
| Поддержка | форма никуда не отправляет | API обращений, защита от спама |
| Ошибки | только экран ошибки | мониторинг (Sentry или аналог) из `AppErrorBoundary.componentDidCatch` |

**Хранение данных.** В localStorage сейчас лежат ФИО, телефон и почта из черновиков заявлений
(`epasluga-draft:*`), состав семьи, даты рождения и платежи «Далони», статусы заявлений. В продукте
так нельзя: localStorage читает любой скрипт страницы (XSS) и все, у кого есть доступ к устройству,
данные не шифруются и не удаляются при выходе. Персональные данные — только на сервере; на устройстве —
максимум кэш без персональных данных и черновики, удаляемые при выходе.

**Заголовки хостинга.** `<meta>` CSP не поддерживает `frame-ancestors`, поэтому на сервере нужно
отдать заголовками: `Content-Security-Policy` (та же политика + `frame-ancestors 'none'`),
`Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
`Permissions-Policy`. `sw.js` и `index.html` — с `Cache-Control: no-cache`, `assets/*` — надолго (имена с хешем).
Когда появится домен — `og:image`/`og:url` с абсолютными адресами, `canonical`, `robots: index`.

**Юридические коды процедур** в `servicesExtra.ts`, `situations.ts`, `situationPassports.ts` в этой
ревизии не менялись — их проверка в отчёте `BA-проверка-кодов-процедур.md` (папка курса) и в разделе
«Паспорт ситуации и юридическая верификация» выше.
